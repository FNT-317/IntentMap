# Requirement discovery

## Purpose

Help the user and IntentMap reach the same clear understanding of the problem, the people affected, the desired result, and important limits. Do not turn the idea into a feature list or technical solution during this module.

## Start from what is already known

First absorb everything the user has said and any relevant project context. Record information under four conceptual states:

- **Stated:** the user said it, but it has not yet been reflected back and confirmed.
- **Confirmed:** the user explicitly agreed that IntentMap's understanding is correct.
- **Suggested:** IntentMap offered it as an example, interpretation, or recommendation.
- **Uncertain:** it is unknown, vague, contradictory, or awaiting confirmation.

One statement may answer several discovery areas. Record all of them and do not ask for the same information again.

## Areas to understand

Use these as a coverage map, not a questionnaire:

1. Why the user wants to build this.
2. What problem exists today.
3. How the user currently handles the problem.
4. What is frustrating about the current approach.
5. Who will use the product.
6. When, where, and on what device it will be used.
7. What the user is trying to accomplish.
8. What a normal use from beginning to end might look like.
9. What seems essential.
10. What may be optional or useful later.
11. What the user likes or dislikes in similar products.
12. What the user definitely does not want.
13. Important limits, including privacy, money, time, platform, and simplicity.
14. What would make the user say the result is successful.

Not every request needs all fourteen areas. Explore only the areas whose answers could materially change the understanding or prevent costly misunderstanding.

## Adapt the depth

Use shallow discovery when the request is small, concrete, low-risk, and already clear. For example, a request to change one button's color may need only a brief restatement and one missing detail such as the desired color.

Go deeper when the request describes a new product, affects several kinds of people, contains unclear goals, has meaningful privacy or cost limits, would be expensive to reverse, or mixes many possible needs.

Depth is sufficient when:

- the underlying problem and desired result are clear;
- the main users and relevant setting are understood;
- important limits and exclusions are known, or explicitly marked uncertain;
- contradictions affecting the direction have been resolved;
- remaining unknowns would not change the shared understanding of the need.

The goal is enough useful understanding, not a long interview.

## Discovery loop

1. Review the current stated, confirmed, suggested, and uncertain information.
2. Select the highest-value unknown using [dynamic-questioning.md](dynamic-questioning.md).
3. Ask one main question in plain language.
4. Update every area answered by the user's response.
5. When a meaningful piece becomes clear, reflect it back using [confirmation-checkpoints.md](confirmation-checkpoints.md).
6. If the user corrects it, update the understanding and continue from the corrected information.
7. Repeat only while an important discovery gap remains.

## End of Module 1

Give a short plain-language summary covering the problem, who experiences it, what result matters, the relevant setting, known limits, and any remaining uncertainty. Clearly distinguish the user's decisions from IntentMap's interpretations. Ask the user to confirm or correct the summary.

Do not mark discovery complete until the user explicitly confirms it. Only after that confirmation may scope definition begin.
